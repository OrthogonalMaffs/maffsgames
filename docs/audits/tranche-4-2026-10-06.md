# Tranche 4 audit: 10 games, answer keys checked: main at `fc20f8c`, read-only

I changed nothing in the repo while auditing. The banks were extracted on a scratch export of `fc20f8c` (82 live, 1
static, 14 generator, as the sandbox recipe expects), and every game was played in Chromium with analytics stubbed,
Firebase replaced by an inert stand-in and `submitScore` intercepted: no event or score left the machine, and no
leaderboard submission was made. One audit agent per game did the first pass; I went back to the source for every
CRITICAL and HIGH below, read the line and redid the arithmetic (independent scripts for Glorious Gantt's critical
path analysis and Screening Room's gut-check bands; by hand for the rest). The MEDIUM and LOW findings are the agents'
evidence; the ones I spot-checked are named in §3.

**Grading calls of mine, for consistency with tranches 1-2:**
- A `?level=` crash on a hand-typed URL (`constructor`, `__proto__`) that leaves the page recoverable by pressing a
  level button is MEDIUM in every game; a silent fallback alone is LOW, unless it also writes a stray leaderboard
  board (MEDIUM).
- An unstated precision where the marking is unaffected (multiple choice, options far apart) is MEDIUM (SR-1), as in
  tranche 2. Where the stated tolerance then marks a correct answer wrong it is HIGH.
- A double-click or double-tap that answers the next question unseen is HIGH (as Spot the Muppet in tranche 2); one
  that only needs two Enter presses inside one frame is LOW or MEDIUM, by reach.
- Linear Equation Solver's CRITICAL is already known and queued (todo START batch 1, SR-13). It is counted, not new.

**No STOP IF fired.** Nothing suggests personal data is collected; no security problem was found.

### Glorious Gantt (Core, Level 4: critical path analysis)
Root cause for most of what follows: each scenario's `nodes` and `arcs` (an activity-on-arc network with hand-typed
early/late times) are written by hand beside its `activities` table and never derived from it. 13 of 15 networks do
not encode their own table. My own recomputation from each table (forward and backward pass, every float, every
zero-float set) and over the drawn arcs agrees with the agent's.
- **CRITICAL (JC on counting), Level 4 mode A.** The prompt is "Enter the early/late time for Node n", so the drawn
  network is the question. 7 node-time keys contradict the drawn arcs, and with the wrong critical path (L4_A2) and
  the two float-E items (L4_A3) that is 10 or more of 82 marked entries (12%):
  - **L4_A1 (:353, arcs :373-380):** H is a self-loop (from 6 to 6), invisible. F (2) and G (3) enter node 6 from node 5
    (early 22), so node 6 early is 25; the key is 28 (wrong by the table too: ES(H) = 25). Node 5 late keyed 22; the
    arcs give 25.
  - **L4_A2 (:390):** H a self-loop at node 8; E drawn from node 1 although it depends on A; node 6 a dead end. Node 5
    early keyed 4 (arcs 3), node 8 early keyed 9 (arcs and table 7), node 7 late keyed 6 (arcs 8), node 6 late not
    derivable.
  - **L4_A3 (:428):** F ends at node 7 but G starts at node 5; node 6 late keyed 20, arcs give 24.
  - Counting only keys wrong under every reading, it is 5 of 82 (6%), which would be HIGH. Hence JC.
- **HIGH, CM_A3 (:284, floats :311): float of C keyed 7, true 4.** F depends on C but is drawn as a self-loop at node
  4. By the table F runs 4-7 with LS(F) = 8, so LF(C) = 8 and float(C) = 8 − 0 − 4 = 4. The Gantt chart draws F at
  days 11-14, past the 13-day axis.
- **HIGH, L4_A3 (:460, :464): float of E keyed 15, true 10; "10 days" is offered as a wrong option.** E runs 5-10;
  T = 28, LS(G) = 23, so LF(F) = 23, LS(F) = 20, LF(E) = 20 and float(E) = 20 − 5 − 5 = 10. Both
  the Step 5 float key and the Gantt question "Activity E (Marketing) has how many days of float?" (keyed '15 days',
  '10 days' among the wrong) mark the right answer wrong.
- **HIGH, CM_B1 (:507, :534): two critical paths, only one accepted.** A→B→D→G = 1+4+5+1 = 11 and A→E→F→G = 1+6+3+1 =
  11. Selecting A, B, D, E, F, G is answered "E, F have float — not critical". The same scenario's floats (:535) key
