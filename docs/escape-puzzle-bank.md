# Escape-room puzzle bank — audited

**Source:** Gemini, 2026-08-26, 20 diegetic puzzle concepts. Verified computationally the same
day; the verification script is in the commit that added this file.

**Status, 2026-08-31: four batches audited, 18 locks in service, 85 number sets across them.**
Rooms C–H are built from `lock-bank-batch3.txt` and `-batch4.txt`, all passing
`scripts/check-lock-bank.py`. Batch one's rejects (the laser mirror, the bookshelf lever) have never
been repaired, which is why rooms A and B cannot be built. Everything below is the audit trail,
oldest first.

**The 18 locks are now 18 lock *families*.** Each one carries a library of 2–5 verified number sets
and draws one per play, so a room can be replayed without repeating itself. The libraries live in
`escape-rooms/variants.json`, are injected into each `room.js`, and are generated by
`scripts/gen-escape-variants.py` — **never write one by hand.** The generator applies every rule
this document argues for, mechanically, to every candidate:

- exactly one setting on that instrument's own grid solves it — the rule the whole bank exists for
- the answer is actually settable: on the step, inside the range
- the misconception is settable too and is not the answer, or its response could never fire
- **no number printed in the clue equals the answer** — the trap this file notes the checker cannot
  see, now checked directly rather than by reading
- the answer is not at either end of the travel, where dragging to the stop would find it
- the answers in one library are spread out, so five sets are five different rooms

Of 786 candidates it considered, 701 were rejected and 85 kept. **Variant 0 of every lock is the
audited bank lock below, unchanged**, and `scripts/check-escape-rooms.py` fails if that ever stops
being true, if `room.js` drifts from `variants.json`, or if a `{{token}}` in the prose cannot be
filled by every variant of its lock.

**The honest summary: the generation is strong and the checking is not.** Fourteen of the twenty
are correct as written and several are better than anything currently in `the-perfect-prank`.
Six have real faults, and three of those are fatal for an escape room specifically, because
**a lock needs exactly one answer.**

That is a useful division of labour rather than a criticism. Inventing twenty diegetic instruments
across twenty topics is the hard, creative half. Checking that each one has a unique solution is
the mechanical half, and it is the half that has to happen before anything gets built.

## A standing rule, added 2026-09-08 — bounds questions ask for the MINIMUM

**Never ask for the greatest value a rounded measurement could give.** A length recorded as
`D` cm to the nearest centimetre lies in `[D − 0.5, D + 0.5)`. The upper bound is a **supremum that
is never attained**: a depth of exactly `D.5` rounds *up* to `D + 1`, so it could not have been
written down as `D` in the first place. Asking for the greatest volume therefore asks for a volume
the object cannot have, and a student who spots that is right and is marked wrong.

The lower bound has no such problem — `D − 0.5` does round to `D` — so **the minimum is real and is
actually reached**. Bounds locks ask for the smallest value.

`hamster-feeder-bounds` shipped the wrong way round and was corrected on 2026-09-08 (Jon's catch:
*"9.5 would round UP to 10"*). Its own AHA line had admitted the problem all along — "even though
nothing measures exactly that" — which is worth remembering: **an audited lock can carry its own
disclaimer and still be wrong.** A note in a bank entry excusing a result is a defect report, not a
justification.

## Broken — do not build until repaired

### #6 Vending Machine Hopper — **two valid answers**
`2x + 5y = 37` with an odd coin count has **two** solutions:

- 16 × 20p + 1 × 50p = 17 coins
- 6 × 20p + 5 × 50p = 11 coins

Gemini spotted both and wrote "select either", which is fine for a worksheet and fatal for a lock.

**Repair:** add "and as few coins as you can manage" → forces `6 × 20p, 5 × 50p`. The extra
constraint also makes it a better puzzle, because it stops the first solution found from being
the end of the thinking.

### #17 Library Bookshelf Lever — **two answers, and an impossible ruler**
`30d₁ + 40d₂ = 120` on 0.1 m notches has two solutions: (1.6, 1.8) and (2.0, 1.5). It is also
described as a **metre** ruler while both answers sit beyond 1 m.

**Repair:** fix one weight's position and solve for the other. Pin the 30 N at 2.0 m, and the
40 N must supply 120 − 60 = 60 N·m, so d = **1.5 m**. Unique, and still a genuine moments problem.

### #3 Laser Tripwire Deflector — **incoherent as stated**
A mirror reflects an *incoming* ray to an *outgoing* one, and the incoming ray is never given.
The working takes the gradient from the mirror (4,3) to the sensor (7,9) — that is the outgoing
beam — and sets the mirror perpendicular to it. A mirror perpendicular to a ray sends it straight
back along itself, so as written the beam returns to the mirror rather than reaching the sensor.

**Repair:** either specify the source and require the mirror to bisect the angle between incoming
and outgoing rays (A-Level and genuinely hard), or drop the optics and make it an honest
perpendicular-gradient puzzle without the reflection claim.

### #5 Server Room Thermal Bounds — **arithmetic error**
145 × 2.45 = **355.25**, not 355.225. Also worth noting for teaching: both are *upper* bounds, so
the true maximum is strictly less than 355.25 — the dial value is a supremum that is never
actually reached. That is a good discussion point rather than a flaw, but the arithmetic is wrong.

### #8 Fire Escape Ramp — **the answer breaks its own safety rule**
Exact distance is 6.0183 m. Rounding *down* to 6.0 m gives an incline of **28.07°**, which exceeds
the stated 28° maximum. The puzzle's own answer fails the puzzle's own constraint.

**Repair:** ask for the base distance to 1 d.p. that keeps the ramp within limits → **6.1 m**. This
turns a rounding slip into the actual lesson: with a safety bound you round the safe way, not the
near way.

### #12 Smart-Locker Prime Hash — **answer is right, working is not**
2592 is genuinely unique in range (verified by exhaustive search over 2^a·3^b·7^c). But the
published working rejects 2592 explicitly — *"no factor of 7, invalid"* — and then selects it
anyway several lines later. The clue "prime factors include only 2, 3 and 7" reads as requiring
all three, which would exclude the answer.

**Repair:** reword to "it has no prime factors other than 2, 3 and 7" and replace the working,
which is currently a visible trail of guesses.

## What this means for the rooms

These are **lock concepts, not a room.** Each is a single instrument with a single answer, which is
exactly the shape `the-perfect-prank` needed more of — but a room is made by the connective tissue
between locks, not by the locks themselves. The lesson from that build was that difficulty comes
from *not knowing which clue belongs to which lock*, not from harder sums.

Suggested use: treat this as a **bank to draw rooms from**, grouped by level.

- **KS3 room** — 7 (LCM), 13 (similar triangles), 6 (repaired), 17 (repaired), 1 (bearings)
- **GCSE room** — 2 (mixtures), 4 (simultaneous), 19 (decay), 11 (scale factor), 15 (inequalities)
- **GCSE Higher / A-Level** — 10 (vectors), 20 (circle theorems), 16 (congruences), 5 (repaired), 18 (conditional probability)

**Before any of these is built into a room, it needs the uniqueness check run against it.** Six in
twenty is not a bad hit rate for creative generation, but three unbuildable locks reaching a class
would be three lessons stalled.

## Five VERIFY lines needed repair — the puzzles did not

### A VERIFY that cannot fail
Four lines computed the answer and then searched for it:

```python
[n for n in range(101) if n == int(100 * (40/100) * (60/100))]   # returns [24] whatever the clue says
```

This returns exactly one element regardless of whether the puzzle is sound, so it satisfies the
letter of the request while testing nothing. The checker now detects this by AST — a condition
comparing the loop variable to an expression that never mentions the loop variable is a
restatement, not a constraint.

Repairs, each expressing the actual constraint:

```python
biolab      [n for n in range(101) if n*100 == 40*60]
camera      [d for d in range(1,91) if abs(5/math.tan(math.radians(d)) - 12) < 0.3]
airlock     [a+9+11+13+15 for a in range(1,100) if a+9+11+13 == 47]
```

The camera one is the nicest repair: instead of taking arctan and rounding, it asks which whole
degree actually puts the keycard at 12 m. 22° gives 12.38 m and 24° gives 11.23 m, so 23° wins on
the geometry rather than on a rounding rule.

### A minimum is not a uniqueness failure
`gearbox-lcm` used `[[...][0]]` to grab the smallest revolution count. The full candidate set is
15, 30, 45, 60… — correctly *not* unique, because the puzzle asks for the minimum. The format now
has **`VERIFY_MIN`** and **`VERIFY_MAX`** for exactly this, returning the whole candidate set:

```
VERIFY_MIN:  [r for r in range(1,101) if (24*r)%15==0 and (24*r)%18==0]
```

### Exact float equality
`data-decryptor-indices` was rejected for having no solutions, and the maths is fine:

```
6e5 / 1.5e-4  ==  4000000000.0000005     not  4e9
```

A correct puzzle failed on floating point. Repair with a tolerance, or better, integer arithmetic.
**Three locks that passed have the same fragility** and only work by luck:

```python
concrete   ... if a+b==100 and 3*a+8*b==450        # not 0.3*a+0.8*b==45
vault      ... if 5*360 == 120*n                   # not 5*(360/n)==120
pipeline   ... if 12*d == 8*(1200-d)               # not d/8 == (1200-d)/12
```

The checker now warns on any exact `==` involving division or a float literal.

## Verdict

**Twelve usable locks** once the five VERIFY lines are repaired — nothing needs rewriting as a

that is a large step up.

Timing is the remaining unknown. Every estimate came in at 2–4 minutes, which is right for a
15-minute room, but those are estimates by the author of the puzzle. Worth timing the first room

## What was wrong

### One fatal: `dj-deposit-compound`

£800 at 5% compound for 4 years is **£972.405**, not the £972.40 the clue states. There is no
number of whole years that puts the balance at £972.40, so the lock has no answer, and the checker
said so. This is the first batch-3 lock to fail on maths rather than on verification.

It also had a quieter fault. The stated misconception — reasoning with simple interest — gives
344.81 ÷ 80 ≈ 4.3, which rounds to **4, the correct answer**. A trap that opens the lock is not a
trap.

**Repaired:** £1000 at 10% for **5 years = £1610.51**, exact to the penny. Simple-interest
reasoning now gives 610.51 ÷ 100 ≈ 6.1 → 6, which is wrong, so the misconception costs a penalty
the way it should. 5% only lands on whole pence for four years from £1600; 10% from £1000 is
clean for five.

### A new failure class: the answer is printed in its own clue

Two locks were mathematically sound and still unbuildable, because the correct value could be read
straight off the clue without doing anything:

| Lock | As sent | Problem |
|---|---|---|
| `dodgeball-pressure-boyle` | 20 m³ at 45 psi → 30 m³ | Answer **30**, and "30" is in the clue |
| `wifi-venn-router` | 80 devices, 45 S, 35 Y, **15 neither** | Answer **15**, and "15" is in the clue |

A group that dials in a number they can see, gets a green light, and moves on has learned that
guessing works — which is exactly the behaviour the penalty clock exists to suppress.

**Repaired** by changing the numbers, not the puzzles: 20 m³ at 60 psi → 25 m³ gives **48 psi**;
80 devices with 48/37/12 gives **17 both**. Neither value appears in its own clue.

**This is worth adding to the brief.** The checker tests that exactly one value opens the lock; it
cannot test whether that value is guessable from the clue text. Rule: *no lock's answer may be a
number the student can read off the clue.*

### VERIFY, again — two tautologies and five exact-float comparisons

```python
[a for a in range(1, 101) if a == 90 * (5/15)**2]        # elbow patch: computes, then matches
[n for n in range(1, 101) if n == math.factorial(4) / math.factorial(2)]   # keyboard: ditto
```

Both are the batch-2 pattern the checker now catches by AST. Rewritten as constraints:

```python
elbow patch   [a for a in range(1, 101) if a * 15**2 == 90 * 5**2]
keyboard      [n for n in range(1, 101) if n * math.factorial(2) == math.factorial(4)]
```

Five more used exact `==` on floats. The vault trajectory is the instructive one: it **passed**,
because `-2*(1.2)**2 + 4.8*(1.2) + 0.12` happens to land on exactly `3.0` in binary floating point.
Passing by luck is what batch 2 warned about, so it was rewritten over `Fraction`, sampling t in
tenths of a second and taking the genuine maximum rather than trusting a precomputed vertex.

[v for x in range(1, 50) for v in [x**3] if 6 * (x**2) == 1350]

[f for f in range(51) if 20 < 3*f - 5 < 32 and f > 1 and all(f % d for d in range(2, f))]

# Batch 5 — 2026-08-31

Two rooms, six locks: **`docs/lock-bank-batch5.txt`**, `6 locks, 6 usable, 0 rejected`.
Written by Jon rather than by Gemini, and sent with the VERIFY lines already in place and already
single-valued. **Nothing was wrong with the mathematics in any of the six**, so what follows is
about instruments and house rules, not repairs.

## What was changed

**Two answers sat on an end stop.** `canteen-mean-calories` was specified as a slider from 100 to
1000 kcal with an answer of 100 — the bottom of the travel. `gen-escape-variants.py` refuses any
variant whose answer lands within 4% of either end, for the obvious reason: an instrument already
resting on the answer is not a lock, and a student who drags to the stop and lets go has solved
nothing. The slider now runs from 0. Nothing else about the lock moved.

**Two dials were finer than they needed to be.** `visitor-space-bounds` reads to 2 dp over 0–20
litres, which is two thousand draggable positions for a lock whose answers are all quarters — both
measurements are to the nearest metre, so both lower bounds end in .5 and every product lands on
.25 or .75. It now steps in 0.25 and still reads 2 dp. `boom-gate-sector` steps in 5°, which every
angle in its library divides into. The typed fallback is unaffected in both cases.

**Two locks arrived with a second misconception each** — 108 kcal on the mean and 14.25 litres on
the bounds. The engine names *one* misconception per lock, because the response is written prose
that says what went wrong by name, and it fires on exactly one value. The first of each pair was
kept. The mean's second — averaging the four items already entered — is now in that room's teacher
notes as something to listen for. The bounds' second was dropped outright: it is annotated "using
5.5 and 2.5 but adding them instead of multiplying", and 5.5 + 2.5 is 8, not 14.25. The number and
the reasoning given for it do not describe the same mistake, so there was nothing to build.

**The VERIFY lines were rewritten to enumerate the instrument's own grid** and to compare exactly.
Three of the six compared floats:

```python
[ang for ang in range(181) if (ang / 360) * 2 * math.pi * 3 == 0.75 * math.pi]
```

That one happens to be true — 45/360 is exact in binary and so is 0.75 — but it is true by luck,
and the next set of numbers through the same expression will not be. It now cancels the pi and
compares rationals, which is also how a student does it:

```python
[deg for deg in range(0, 181, 5) if Fraction(deg, 360) * 6 == Fraction(3, 4)]
```

## Notes for building

- **`ev-charger-quadratic` is the same shape as `canteen-freezer-inequality`** (batch 4): an

- **`cookie-price-simultaneous` is the second `pair` lock** (`rugby-scoreboard-bases` is the other)

- **`kale-fraction-drain` teaches by the gap between the clue and the instrument.** The letter

- **Times total 10 minutes for room 9 and 9 for room 10**, both comfortably inside the fifteen.

## Cross-lock collisions — a rule for every room from here

Each library is still verified lock by lock, but since `0907f6e` the engine draws a room jointly and
`check-escape-rooms.py` counts the **VALID** combinations: no clue figure in two locks' clues, no answer in
another lock's clues, no answer equal to another lock's misconception, no shared answers (the first two
ignore figures of 2 or less). **A new room needs at least 20 VALID combinations** and should have a VALID
variant 0. Check a new batch's figures against the other locks in its room, not only against its own clue.
