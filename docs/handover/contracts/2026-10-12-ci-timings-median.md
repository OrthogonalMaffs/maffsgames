TASK (home lane, CI-TIMINGS-MEDIAN): Make the recorded CI timings robust to one slow run, so a single noisy main run can never turn every PR red, and unblock main now.

ROOT CAUSE: `record_timings()` in scripts/ci-groups.py overwrites scripts/ci-timings.json with ONE run's figures, and takes `setup` as the MAX of that run's group setups. Main run 785 (38224711265, the factor-race merge) had one slow group: its recorded setup was 125 s, against 18-28 s on every one of the previous 11 records in git history. Line times barely moved. Growth and Decay's 94 s is within its usual 55-98 s range. `--write-pack` then repacked against a setup of 125 s, so every group carrying a long single line (Just Pythag It, Bruv parts 1-4, Free Daily Pizza, Equation Builder parts 1-2, Answer lock part 1 and others) is estimated past 80% of budget, and `ci-groups.py --check` fails on main at ef82d88 and on every PR (12 groups, 81-108%). Two further faults turn noise into a deadlock: (1) the "CI timings and pack" job commits the new pack without running `--check` on it (check-site.yml, timings job, around line 201-210); (2) that job only runs after a green Gate, so a bad pack can never be repaired by main itself. The cloud lane is stopped at VERIFIERS-20 game 6 (#287) on this.

CLASS CHECK: Yes. This is shared infrastructure called on every PR in both lanes, and the bug is the absence of safety in it (a single sample treated as truth; a generated file committed unchecked). So the fix goes in the recorder and in the job that commits its output. It does not go in the pack file, the budgets, or any verifier. Hand-editing ci-pack.json, raising TARGET/FAIL or the timeouts, or splitting the long lines just to get under a 125 s setup would each be a call-site patch on a measurement bug, and are all excluded below.

EXACT CHANGE (one PR, branch claude/ci-timings-median, a new worktree from origin/main):

The estimates that `pack()` and `budget_faults()` read become the MEDIAN over that history: per line, over the runs that timed it; and for setup, the median of each run's setup (each run's setup stays its max group setup, which is conservative within a run). A line timed in fewer runs uses the median of what it has. Keep the existing top-level fields (`run`, `date`, `setup`, `lines`) holding the medians, so every reader of the file is unchanged. Describe the new rule in the module docstring.
2. Seed the history now from git: the last 5 versions of scripts/ci-timings.json on main that came from real runs, excluding none (the median handles 25f887b's outlier). Write the medians, then run `python scripts/ci-groups.py --write-pack` and `--check`. --check must pass.
