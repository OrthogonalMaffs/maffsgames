# Standing rules for STOP IFs (Jon, 27 Oct 2026), verbatim

For every contract from now on unless it says otherwise. Recorded by the cloud lane; canon §0.3 is the home lane's to update.

> Standing rules for STOP IFs (Jon, 27 Oct), for every contract from now on unless it says otherwise. A STOP IF means "don't do the risky thing": it doesn't mean sit idle. Apply these defaults, record each in your report under "Decided for you", and keep working:
>
> * Too few questions for a stage or type: widen the ranges within the same tier and topic until it meets the minimum, and list what you widened. Stop only if it's still short.
> * It won't fit the phone or laptop rule: park that item with screenshots and measurements, put it on the known-failures list with its reason, and carry on with the rest of the contract.
> * It needs a shared file another lane holds: write the change on its own branch, don't merge it, report it, and carry on with everything else.
> * Main is red because of another lane: keep working and keep PRs ready. Only the merge waits. Never override it yourself.
> * The count goes past a STOP IF threshold (e.g. "more than 3 games"): finish the rest, then report the list and the counts together, not one at a time.
> * Wording, layout, names, test structure: decide, and list it for Jon.
> * Still a real stop: a mathematically wrong answer you can't resolve; anything collecting new data; deleting or overriding anything; a design question with no reasonable default. For those, park the item, write the exact question in the handover, and move to the next queued item. If the queue is empty, say so and stop.
