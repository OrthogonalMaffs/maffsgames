TASK (home lane, SCI-CALC): Give the shared on-screen calculator a
scientific key set that a game can ask for, and use it in Growth and
Decay first. (Jon, 9 Oct 2026: "we should have a scientific calculator
to hand when the students need it.")

ROOT CAUSE: MaffsCalc (schools/assets/calculator.js) supports only
+ − × ÷, ², √, brackets and Ans. That was by design (canon §4.4): the
keys a Pythagoras or percentages question needs, and nothing more.
Growth and Decay's questions need a general power (1.05^10), ln, log
and e^x, so a student without a scientific calculator cannot do them
on the site. Other games (trigonometry, logarithms, exponentials) have
the same gap. There is no way today for a game to ask for more keys:
the roster's Calculator field is either `required` (the basic
calculator) or no calculator at all.

CLASS CHECK: Shared infrastructure and a missing capability that
several games need. It is fixed once in calculator.js and
check-calculator.py, with a declared opt-in, so every game that needs
it gets the same, tested engine. No game builds its own. The basic key
set stays the default and stays unchanged, so the Essentials games keep
the simple keypad.

EXACT CHANGE:
1. Roster and canon §4.4: a new Calculator value, `scientific`,
   meaning a calculator is required and the scientific keys are shown.
   Start-screen badge: "Scientific calculator required". Update the §4.4
   table, and the VALUES and badge rules in check-calculator.py: a
   `scientific` game loads calculator.js and keypad.js and shows its
   badge; `required` behaves exactly as now.
2. calculator.js, engine (evaluate). Add:
   - xʸ as ^, right-associative (2^3^2 = 512), binding tighter than
     unary minus (-2^2 = -4, as ² already does);
   - functions that open a bracket like √(, closed on = as now: ln(,
     log( (base 10), e^(, sin(, cos(, tan(, sin⁻¹(, cos⁻¹(, tan⁻¹(;
   - constants π and e, with implicit multiplication (2π, 3e^(1));
   - an angle mode, DEG by default and switchable to RAD, shown in the
     display. Trig uses it, and the inverses return in it.
   Errors (the display shows "Error", as now): ln or log of 0 or a
   negative; sin⁻¹ or cos⁻¹ outside [−1, 1]; tan at an odd multiple of
   90° (or of π/2 in RAD), detected exactly for whole-degree inputs
   rather than returning 1.6e16; a result that is not finite. The
   10-significant-figure display rule stays.
3. calculator.js, UI: mount(el, {keys: 'scientific'}) adds the extra
   keys; mount() without it is unchanged, key for key. The scientific
   keys fit the panel at 320, 390 and 412 px wide with 48 px keys on a
   phone (a second key block that scrolls inside the panel is fine; the
   page itself never scrolls sideways). The docked desktop panel keeps
   its rules.
4. scripts/test-calculator-js.py: add cases, each exact to 10 s.f.:
   - 1.05^10 = 1.628894627; 2^3^2 = 512; -2^2 = -4;
   - ln(e) = 1; log(1000) = 3; e^(ln(5)) = 5; 2π = 6.283185307;
   - DEG: sin(30) = 0.5, tan(45) = 1, sin⁻¹(0.5) = 30;
   - RAD: sin(π÷6) = 0.5;
   - Errors: ln(0), log(-1), sin⁻¹(2), tan(90) in DEG.
   Plant a left-associative ^ and a missing tan(90) guard in the
   self-test; each must fail. A test that mount() without keys renders
   exactly the current key set (no new key appears in the basic
   calculator).
5. Growth and Decay: Calculator field `scientific`; the page loads
   calculator.js and keypad.js and shows the badge; mount it with
   {keys: 'scientific'}, and with {answer: input} only if the game's
   answers are typed. Check in Chromium that one full question can be
