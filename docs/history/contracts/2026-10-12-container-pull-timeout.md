TASK (home lane, CONTAINER-PULL-TIMEOUT): Stop the container image pull from counting against a check group's time limit, so a slow registry no longer cancels jobs that never ran a check.

ROOT CAUSE: Every check-site and content job runs in the Playwright container (mcr.microsoft.com/playwright/python:v1.63.0-noble). GitHub counts "Initialize containers" (the image pull) inside the job's `timeout-minutes`, which is `matrix.timeout` (6 min for content groups). The workflow assumes a start-up of about 30 s fits in the budget's 25% headroom (check-site.yml, comment above "Mark the workspace as a safe git directory"). On 12 Oct that failed repeatedly. Main run 802 (bb79123) had 8 jobs cancelled at Initialize containers on attempt 1. On attempt 2, Content verifiers 33 spent 379 s initialising against its 360 s timeout, so it was cancelled before its first step (recorded in docs/handover/cloud.md, 12 Oct). PRs #291 and #292 hit the same pattern. A timed-out job shows as "cancelled", and the cloud lane is re-running jobs by hand on Jon's interim rule. `matrix.timeout` is doing two jobs: hang guard for the whole job, and the group's time budget. Only the second should depend on the checks.

CLASS CHECK: Yes. This is shared infrastructure: every container job takes its timeout from the same matrix field, in the site-wide matrix and in the groups that ci-groups.py emits. Fix it where the timeout is defined, by separating the job's hang guard from the group's budget. Do not fix it per job. Raising `matrix.timeout` itself would loosen the group budget the budget step and ci-groups.py --check enforce (canon §7.8.1), and per-job re-runs are a workaround: both are excluded.

EXACT CHANGE (one PR, branch claude/container-pull-timeout, a new worktree from origin/main):
1. Add a second timeout field, `job_timeout`, to every container job's matrix entry. It equals `timeout` plus a pull allowance of 10 minutes. GitHub expressions cannot add numbers, so the value is emitted, not computed in YAML:
   - scripts/ci-groups.py: each emitted group (the matrix entries, around lines 249 and 296) gains `"job_timeout": timeout + PULL_ALLOWANCE`, with `PULL_ALLOWANCE = 10` defined once beside TIERS, with a comment citing run 802's 379 s.
   - .github/workflows/check-site.yml, the static check-site matrix: each entry gains a literal `job_timeout` equal to its `timeout` + 10. Add a ci-groups.py selftest (or the site-wide check that already reads this file) asserting job_timeout = timeout + PULL_ALLOWANCE for every entry, so the two cannot drift.
2. check-site.yml: both the `check-site` and `content` jobs use `timeout-minutes: ${{ matrix.job_timeout }}`. The budget step keeps `TIMEOUT_MIN: ${{ matrix.timeout }}` unchanged, so the group's budget is still 75% of `timeout`, measured from JOB_T0, which starts after the container is up.
3. Rewrite the comment above "Mark the workspace as a safe git directory": container start-up is outside the budget (job_timeout carries a pull allowance); the budget clock starts here.
4. Record the pull: in the budget step's summary, print the seconds from the job's start to JOB_T0 if the runner exposes it (the job's started_at is not available inside the job; if there is no reliable in-job source, skip this point and say so in the PR rather than adding an API call).
5. Canon §7.8.1: one sentence. A job's hang guard is `job_timeout` (the group's timeout plus a 10-minute pull allowance); the group's budget is still 75% of `timeout`, from its own clock. Cite run 802.
6. docs/handover/home.md: a dated entry. Say the cloud lane's interim rule (re-run jobs cancelled at Initialize containers, up to 3 times) can be retired once main has had two full runs with no such cancel. The cloud lane removes it in its own handover; do not edit docs/handover/cloud.md.
7. `python scripts/check-changed.py` before the first push (this PR changes CI, so every check runs). Merge on a green Gate with main green. Watch main's full run and report it. Remove the worktree and branch per CLAUDE.md as it stands. Note: RULINGS-12OCT replaces that step later.

DO NOT TOUCH: TARGET and FAIL, TIERS' timeouts and budgets, the budget step's arithmetic, the timings job and the median logic (#288); the container image and its pinned version; any verifier, game or findings file; docs/handover/cloud.md; the cloud lane's open PRs.

SUCCESS CONDITION: Every container job's `timeout-minutes` is `matrix.job_timeout` (= timeout + 10). The budget step still reports against 75% of `timeout`.
