TASK (home lane, GA4-LIVE-ONLY): Load Google's tag only on the live site, from one shared place, so no test run, local server or preview can send a page view or session to GA4.

ROOT CAUSE: 150 published pages (97 games, 23 escape-room pages, 21 parent guides, the portal, Essentials, /op/, about, feedback, leaderboards, privacy, spec map, updates; main 12 Oct) each carry their own copy of the gtag snippet in <head>: `gtag/js?id=G-992JLHLP2D` and `gtag('config', ..., {send_page_view:true, storage:'none', anonymize_ip:true})`, with no hostname check. Any browser that opens a page sends a page view and session to GA4, wherever the page is served from. schools/assets/analytics.js already gates `mfg()` events to maffsgames.co.uk (its "Production only" block), so key events and the Google Sheet are clean, but the head snippet is outside that gate. check-site.py blocks Google's hosts; most per-game verifiers, which launch their own Chromium, do not, and serve-stubbed.py swaps analytics.js but leaves the snippet. Jon's GA4 (12 Sep - 11 Oct) shows 112 active users at 800×600 (headless Chrome's default screen) with 2 s average engagement and 0 key events, against 976 in total; the daily count spiked on 3 Oct, when the full local suite still ran before every push. Some of these will be crawlers, which this change cannot stop. Test traffic it can.

CLASS CHECK: Yes. The same snippet is copied into 150 pages, so the safety cannot be added in one place today. The fix moves the tag to the one shared file every page loads, behind the hostname gate that file already uses, and a CI check stops a page carrying its own copy again. Adding GA-host blocking to each verifier would be the call-site patch, and is excluded (one existing exception stays: see step 4).

EXACT CHANGE (one PR, branch claude/ga4-live-only, a new worktree from origin/main):
1. schools/assets/analytics.js: at load, if and only if `location.hostname` is maffsgames.co.uk or www.maffsgames.co.uk, inject gtag.js for G-992JLHLP2D and configure it exactly as the snippet does now (send_page_view:true, storage:'none', anonymize_ip:true; same page_view on load). Define `window.dataLayer` and `gtag` before anything calls `mfg()`, so an event fired early is queued, not lost. On any other host, define nothing that sends: `mfg()`'s existing gate already returns.
2. Every page: remove the head snippet (both script tags), and make sure the page loads analytics.js exactly once, at the right relative path. Five pages have the snippet but no analytics.js (about, feedback, leaderboards, privacy, spec map): add it. Do it with a script in the pattern of apply-footer.py / apply-meta.py, not by hand. Report the count of pages changed, which must be 150.
3. New scripts/check-analytics-loader.py, in CI as a site-wide check: no published page contains `googletagmanager.com/gtag`, `gtag('config'` or the measurement ID; every published page loads analytics.js exactly once; and analytics.js contains the hostname gate around the loader. Self-test plants: a page with the snippet back, a page with analytics.js twice, a page with none, and analytics.js with the gate removed. Each must fail.
4. Checks that look for the old snippet: scripts/verify-parent-guides.py (its "TPL" check asserts G-992JLHLP2D is in each guide's body), and any line in check-site.py, test-calculator-js.py, check-keypad.py or test-escape-analytics.py that assumes the snippet is in the page. Each now asserts the new arrangement instead (analytics.js present, no snippet). test-escape-analytics.py deliberately serves pages as https://maffsgames.co.uk, so the new loader will fire there: it must keep blocking Google's hosts itself, and its test must show zero requests reaching them. Add that assertion if it is not already there.
5. Prove it in Chromium: on the stub server, a game page makes no request to googletagmanager.com or google-analytics.com. Under the emulated live host (as test-escape-analytics does, with Google's hosts routed to a recorder rather than the internet), exactly one gtag.js load and one page_view are attempted, with the same config parameters as before.
6. Canon §1 (analytics) and .claude/rules/analytics.md: one line each. GA4's tag is loaded only by analytics.js and only on the live host (12 Oct 2026). Cite the 800×600 evidence. Note that crawlers still reach GA4, and filtering them is a separate decision. Also tell Jon in the PR and the handover: data collected before this merge still includes test traffic, so exclude 800×600 in any report on dates up to the merge.

That is the only live load in this task, and it is a real page view, so say it was one. Remove the worktree and branch with scripts/end-task.py.

DO NOT TOUCH: the measurement ID and the config values; mfg()'s gate, its events and the Sheets endpoint; analytics.js's abandon logic; Firebase; any game's logic; GA4 property settings (Jon's); docs/handover/cloud.md.

SUCCESS CONDITION: No published page carries the gtag snippet. Every page loads analytics.js once. On any non-live host no request reaches Google's analytics hosts. On the live host the tag loads and sends page_view with the same configuration as before. check-analytics-loader.py runs in CI and fails on each plant. The checks that expected the snippet assert the new arrangement. Main's full run is green, and one live page load confirms GA4 still receives page views.
