======================================================================
TASK (home lane, LEVEL-RESOLVER): Give every game one shared way to read `?level=`, so an unknown key always falls back to the game's default level, and fix the cause: no link on the site may send a level key its target game does not serve, and no score may reach a board under an undeclared key.

ROOT CAUSE: There is no shared level reader. 55 of 99 game pages read `?level=` with their own code, in at least eight different shapes. The common one, `if (QUESTIONS[p.get('level')]) level = p.get('level')`, treats `constructor` and `__proto__` as valid keys, because they are inherited properties of every object, and the game crashes. Other games pass the raw key straight to `MaffsLeaderboard.submitScore`, which creates a stray public board under whatever was typed. Some ignore `?level` altogether, so the roster's listing for that level is not true. The register holds 19 open class-4 findings across 18 games (canon §0.2, exit-bar point 3, "level resolver"). Jon's ruling, 12 Oct 2026: an unknown key gives the game's default level, and "then we fix the underpinning fault that causes it". The cause is our own links and listings sending keys a game does not serve (for example modular-battle's portal card lists A-Level, which the game has no content for), plus nothing stopping an undeclared key reaching a board.

CLASS CHECK: Yes. The same bug shape is in many components, and the safety is missing at the shared layer. The fix is architectural, in three parts. (1) One shared module that every game calls, in which each game declares its levels and its default once. (2) The leaderboard module refuses any level the game has not declared, so a stray board cannot be created, whatever a game does. (3) A site-wide check that every internal `?level=` link, the roster's listing and the game's declaration agree. Patching each game's own `if` would leave the next game free to repeat the fault, so per-game patches are excluded.

EXACT CHANGE:
PR 1 (branch claude/level-resolver, a new worktree from origin/main): the shared layer and its checks.
1. New schools/assets/level.js, `MaffsLevel`: `MaffsLevel.resolve({ slug, levels: [...keys], fallback })` returns the `?level=` value if it is one of `levels`. The test is membership of the declared array, never a property lookup. Otherwise it returns `fallback`. When it falls back, it replaces the URL's `level` parameter with the fallback using `history.replaceState`, so the page, analytics and any shared link all carry a real key. It shows nothing to the student (Jon, 12 Oct 2026). It records the declaration for the page (`MaffsLevel.declared(slug)`). A game with no levels declares `levels: ['all'], fallback: 'all'`. Stdlib JS only, no dependencies. Document it in canon §4 beside the other shared components.
2. schools/assets/firebase-leaderboard.js `submitScore`: if the page has a MaffsLevel declaration and `level` is not in it, do not submit, and `console.warn` with the slug and key. Games not yet migrated, with no declaration, behave exactly as now, so nothing breaks before migration.
3. New check (site-wide, every PR), for example scripts/check-levels.py:
   a. Every migrated game's declared levels equal its roster levels, mapped through scripts/roster-levels.json (the one table; read it, never copy it).
   b. Every internal link with `?level=` on every published page (portal index.html and its cards' data-levels, /resit/ or Essentials, spec map, leaderboard hub, parent guides, escape-room pages, sitemap.xml) names a level its target game declares, or, for a game not yet migrated, a level the roster lists for it.
   c. A NOT_YET list of unmigrated games, built the way check-answer-lock.py's is (canon §7.6.0). Those games are reported, not failed. The list may only shrink.
   d. Plants: a declaration that differs from the roster, a link to an undeclared key, and a migrated game whose page still reads `?level` with its own code. Each must fail.
4. Tests for level.js in Chromium: `?level=constructor`, `__proto__`, `toString`, an empty key, a mixed-case key, an unknown key and a valid key. Each gives the right level, never throws, and the URL ends up carrying a declared key. Then a submitScore with an undeclared key sends nothing.
5. Where check 3b finds a listing that is wrong (a card, roster row or link for a level the game does not serve), fix the listing to match the game, in this PR. The rule recorded with SR-16 to SR-20 decides it: "A level that serves another level's items is not listed as that level." Do not add content to make a listing true.
PR 2 onward (one branch per batch, each from origin/main): migrate the games in batches of about 10, starting with the 18 games that have open class-4 findings, lowest roster level first. In each game, replace its own `?level` reading with `MaffsLevel.resolve`, use the returned key for everything (questions, analytics, leaderboard, PB), take it off NOT_YET, and close its class-4 findings, citing this contract and Jon's ruling. Skip any game claimed on the cloud lane's `cloud-remaining:` line, and come back to it after the claim is released. Each batch: `python scripts/check-changed.py`, merge on a green Gate with main green, watch main's run, then the next batch.
Final PR: NOT_YET is empty. Set 'level resolver' to True in audit-register.py's SHARED_CHECKS_GREEN. Add a canon §7 line and a home handover entry.
Every PR: a dated docs/handover/home.md entry; remove the worktree and branch with scripts/end-task.py.

DO NOT TOUCH: Firebase data and rules (existing boards stay, SR-11); level keys themselves (keys never change, SR-11); question banks and marking; games' default levels (each game's current default is its fallback, unless the roster contradicts it: then STOP for that game); docs/handover/cloud.md; any game on the cloud lane's claim line.

SUCCESS CONDITION: MaffsLevel exists, is tested, and is documented. No game reads `?level` with its own code (the check fails if one does). Every internal `?level=` link and listing matches what its game declares. The leaderboard refuses undeclared keys. `?level=constructor` and `__proto__` load every game at its default without an error. All 19 class-4 findings are fixed. 'level resolver' is True in the register's point 3. Main's full run is green after each PR.

STOP IF: a game's current default level disagrees with the roster (report which, and do not choose); a game's levels are not knowable from its code without running it (report it and leave it on NOT_YET); fixing a listing would remove a level from a game that teachers actively link to, by GA4 or the Sheet in the last 30 days, if that data is easily available (report it instead of removing it); the leaderboard guard would block a key that currently has live entries under a correct level (list them); a batch's main run goes red.
