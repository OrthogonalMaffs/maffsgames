AMENDMENT to the better-value claims contract. All other fields are unchanged.

EXACT CHANGE, add:
- Measure: crossover. Inputs per option: {fixed, per_unit} (payback: cost as fixed, saving per period as per_unit). The claim gains an optional threshold: {value | none, from: "above" | "at least", discrete: true | false}, with winner = the option that wins beyond the threshold.
- Verifier: n* = (fixed_B − fixed_A) ÷ (rate_A − rate_B). If discrete, the threshold is the first whole n at which the winner is strictly cheaper; a level whole n is "level at n". If continuous, compare within a stated tolerance (state it in the verifier, e.g. ±0.1 for "about"). Equal rates: no crossover. Equal fixed and equal rates: always equal; otherwise the one with the lower fixed cost always wins (threshold none).
- Self-test plants, added: an off-by-one discrete threshold, a wrong winner beyond the crossover, "always cheaper" stated where the lines do cross.
- Map the 12 items (core_024, 025, 026, 027, 028, 029, 030, 033, 038, 049, gcse_019, gcse_020) to crossover. Report in the PR how the existing BREAK_EVEN check relates. Keep it unless the new check fully covers it; removing it is a separate ruling.
- core_031, 037 and 050 mappings are provisional. They stay in the decisions doc with options.

STOP IF, add: any of the 12 has costs that aren't fixed + linear (caps, tiers, stepped pricing). A discrete item's stated threshold disagrees with the first-whole-number convention in a way that suggests the item uses a different, defensible convention. Report it rather than choose.
