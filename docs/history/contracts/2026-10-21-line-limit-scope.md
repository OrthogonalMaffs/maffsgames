# LINE-LIMIT-SCOPE (Jon, 21 Oct 2026), verbatim

TASK: Make the per-line time limit warn on main and fail only the PR that selects the line, so runner noise cannot turn main or every PR red.
ROOT CAUSE: PER-LINE-LIMIT (#465) set the limit equal to the pack target (70%), with no margin, and counted the moving median setup, so a line at 69% tips over on noise. Main run 39559284220: Shape Shifter's median went 155 to 158 s (190 s with the previous 32 s setup, against a 189 s limit) and the setup median rose to 57 s, putting four lines over (Shape Shifter, Equation Builder part 1, Just Pythag It, Bruv part 2, Answer lock part 1). None of the four changed. --record-and-pack treats a line breach as a refusal unless setup alone caused it, so main failed. A pack that did commit a line over the limit would fail --check on every PR.
CLASS CHECK: Yes, a class: shared infrastructure (scripts/ci-groups.py) judging every line, failing where no change is to blame. The fix is in the rule's scope, not a split of the four lines and not a change of figures.
EXACT CHANGE: scripts/ci-groups.py:
1. --record-and-pack (main): a per-line breach never refuses the pack on its own. It is printed as a warning and written to the pack as "split-candidates" (label, median, setup, percentage). The pack is refused only by the group rule (estimate over 80%) and the setup-only path keeps its warning (exit 2). Commit the new pack when only line breaches remain.
2. --check (PR): a line over the limit fails only if the PR's selection (ci-deps select(), as the plan job computes it) includes that line's verifier; any other line over the limit is a warning naming it as a split candidate.
3. Selftests for each path: an unchanged over-limit line on main warns and the pack commits; the same line selected by a PR fails; an unselected one warns; the group 80% refusal still fails; the setup-only exit 2 is unchanged.
4. canon §7.8.1: record the change and Jon's 21 Oct ruling, replacing the 20 Oct per-line wording. docs/handover/cloud.md: list the four split candidates for the home lane.
DO NOT TOUCH: Budgets; the 70% and 80% figures; HISTORY (5); the setup measure; every verifier (no splits in this PR); games/; schools/assets/; any other workflow job.
SUCCESS CONDITION: Selftests pass for every path; on main after merge the timings job passes, commits a pack and lists the four candidates; a PR touching none of them passes --check; check-changed.py finishes before the first push; merged on a green Gate; main's next full run green.
STOP IF: Any group (not line) estimate is over 80% at the current setup, since that is a real refusal: report it with figures and change nothing; the PR's selection is not available to --check without changing the plan job's interface; or the change touches any file outside scripts/ci-groups.py, its selftest, the timings step in .github/workflows/check-site.yml, canon §7.8.1 and the cloud handover.
